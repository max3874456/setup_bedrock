## 2. 모델 가격 업데이트

AWS Bedrock 가격이 변경되면 Lambda 코드의 PRICING dict를 수정해야 합니다.

### 수정 위치

Lambda 콘솔 > `BedrockAthenaLogQueryLambda` > 코드 탭 > `lambda_function.py`


### 현재 적용 중인 가격표

```python
PRICING = {
    # Opus 계열
    "opus-4-8":   {"input": 5.0,  "output": 25.0,  "cache_write": 6.250,  "cache_read": 0.50},
    "opus-4-7":   {"input": 5.0,  "output": 25.0,  "cache_write": 6.250,  "cache_read": 0.50},
    "opus-4-6":   {"input": 5.0,  "output": 25.0,  "cache_write": 6.250,  "cache_read": 0.50},
    "opus-4-5":   {"input": 5.0,  "output": 25.0,  "cache_write": 6.250,  "cache_read": 0.50},
    # Sonnet 5
    "sonnet-5":   {"input": 2.0,  "output": 10.0,  "cache_write": 2.500,  "cache_read": 0.20},
    # Sonnet 4.x 계열
    "sonnet-4-6": {"input": 3.0,  "output": 15.0,  "cache_write": 3.750,  "cache_read": 0.30},
    # Haiku
    "haiku-4-5":  {"input": 1.0,  "output": 5.0,   "cache_write": 1.250,  "cache_read": 0.10},
}
```

### 수정 절차

1. [AWS Bedrock 가격 페이지](https://aws.amazon.com/bedrock/pricing/)에서 최신 가격 확인
2. Lambda 콘솔에서 `BedrockAthenaLogQueryLambda` 코드 편집
3. `PRICING` dict의 해당 모델 가격 수정
4. **Deploy** 클릭
5. 다음 5분 사이클부터 새 가격으로 집계

### 주의사항

- 가격 단위: **USD per 1M tokens** (1백만 토큰당 달러)

## 3. 새 모델 추가

새 Bedrock 모델이 출시되면 **두 곳**을 수정합니다.

### ① PRICING에 가격 추가

```python
PRICING = {
    ...
    "new-model-name": {"input": X.X, "output": X.X, "cache_write": X.X, "cache_read": X.X},
}
```

### ② get_model_tier() 에 매핑 조건 추가

```python
def get_model_tier(model_id):
    m = model_id.lower()
    ...
    if "new-model" in m: return "new-model-name"  # ← 추가
    ...
```

> ⚠️ 매핑 조건의 **순서가 중요**합니다. 더 구체적인 조건을 먼저 배치하세요.  
> 예: `opus-4-8` → `opus-4-7` → `opus` (fallback) 순서

### ③ (선택) MODEL_DISPLAY_NAMES 추가

`BedrocBlockAlertLambda`의 `MODEL_DISPLAY_NAMES` dict에도 추가하면 이메일 알림에 표시됩니다.

```python
MODEL_DISPLAY_NAMES = {
    ...
    "new-model-name": "Claude New Model",
}
```

### 수정 절차 요약

1. Bedrock 콘솔 또는 로그에서 새 모델의 `modelId` 확인
2. `BedrockAthenaLogQueryLambda` > `get_model_tier()` 함수에 매핑 추가
3. 같은 Lambda > `PRICING` dict에 가격 추가
4. Deploy
5. (선택) `BedrocBlockAlertLambda` > `MODEL_DISPLAY_NAMES` 추가 후 Deploy

## 4. 사용자별 예산 한도 변경

### 방법 1: API 호출 (권장)

**엔드포인트**: `PUT https://<budget-api-id>.execute-api.ap-northeast-2.amazonaws.com/prod/budget`  
**인증**: AWS IAM (SigV4)


**파라미터 설명:**

1. AWS 콘솔 > DynamoDB > 테이블 > `bedrock-budget-user-budget`
2. **항목 탐색** 클릭
3. 해당 사용자 항목 선택 (또는 **항목 생성**)
4. `budget_limit` 값 수정 (또는 새로 입력)
5. 저장

**새 사용자 추가 시 필요한 항목:**

### 예산 적용 우선순위

```
1순위: bedrock-budget-user-budget 테이블의 개인별 한도 (최신 month 기준)
```

## 5. 기본 예산 한도 변경 (전체)

개인별 한도가 없는 모든 사용자에게 적용되는 기본값을 변경합니다.

### 수정 위치 (2곳 모두 변경 필요)

| Lambda | 환경변수 | 현재값 |
|--------|----------|--------|
| `BedrocBlockAlertLambda` | `BUDGET_LIMIT` | `60` |
| `BedrockBudget-GetMyUsage` | `BUDGET_LIMIT` | `60` |


### 수정 절차

1. Lambda 콘솔 > `BedrocBlockAlertLambda` > 구성 > 환경변수 > 편집
2. `BUDGET_LIMIT` 값 변경 → 저장
3. Lambda 콘솔 > `BedrockBudget-GetMyUsage` > 구성 > 환경변수 > 편집
4. `BUDGET_LIMIT` 값 변경 → 저장

> ⚠️ **반드시 양쪽 모두** 변경해야 합니다. `BedrocBlockAlertLambda`는 차단 판정, `BedrockBudget-GetMyUsage`는 사용자 조회 응답에 사용되므로, 한쪽만 변경하면 사용자에게 표시되는 한도와 실제 차단 기준이 달라집니다.

## 6. 알림 이메일 설정 (SES)

현재 이메일 알림은 비활성화 상태입니다. 활성화하려면:

### 사전 조건

1. **SES에서 발신자 이메일 인증** (또는 도메인 인증)
   - SES 콘솔 > Verified identities > 이메일 주소 추가
   - 인증 메일의 링크 클릭하여 확인
2. **SES 프로덕션 액세스** (샌드박스 탈출)
   - 샌드박스 상태에서는 인증된 이메일로만 발송 가능
   - 프로덕션 요청 필요 시 AWS Support 케이스 생성

### 설정 절차

1. Lambda 콘솔 > `BedrocBlockAlertLambda` > 구성 > 환경변수
2. `SES_SENDER_EMAIL`에 인증된 이메일 주소 입력
3. 저장


### 알림 동작

- **신규 차단 발생 시**에만 이메일 발송 (이미 차단된 사용자는 재발송하지 않음)
- 수신자: `SES_SENDER_EMAIL`에 설정된 주소 (관리자 메일)
- 내용: 차단된 사용자 정보, 현재 비용, 모델별 사용 내역

## 9. 월초 리셋 확인

매월 KST 기준 1일에 자동으로 새 집계가 시작됩니다.

### 확인 사항

- 이전 월 차단자가 자동 해제되었는지 확인
- CloudWatch Logs > `/aws/lambda/BedrocBlockAlertLambda`에서 `Currently blocked sessions: 0` 확인

### 이상 시 대처

월초에 차단이 해제되지 않는다면:
1. Lambda가 정상 실행 중인지 확인 (EventBridge Scheduler 상태)
2. Athena 쿼리가 새 월 기준으로 실행되는지 확인 (로그)
3. DynamoDB에 이전 월 데이터만 있고 새 월 데이터가 없는지 확인

## 10. 트러블슈팅

### 비용이 집계되지 않을 때

| 순서 | 확인 내용 | 확인 방법 |
|------|-----------|-----------|
| 1 | Bedrock Logging 활성화 여부 | Bedrock 콘솔 > Settings > Model invocation logging |
| 2 | S3에 로그 적재 여부 | S3 콘솔에서 해당 경로 확인 |
| 3 | Athena 테이블 파티션 | Athena에서 `MSCK REPAIR TABLE invocations;` 실행 |
| 4 | Lambda 실행 여부 | CloudWatch Logs 확인 |

### 차단이 되지 않을 때

| 순서 | 확인 내용 | 확인 방법 |
|------|-----------|-----------|
| 1 | 비용이 한도 초과인지 | DynamoDB `bedrock-budget-user-costs` 확인 |
| 2 | 개인별 한도 설정 | DynamoDB `bedrock-budget-user-budget` 확인 |
| 3 | Deny 정책에 포함 여부 | IAM > `BedrockBudgetDeny_*` JSON 확인 |
| 4 | 정책 연결 대상 | 정책 > 정책 사용 탭 > 연결된 역할 확인 |

### Athena 쿼리 타임아웃

- 현재 설정: 50회 × 3초 = 150초
- Lambda 타임아웃: 300초
- 해결: 코드의 `run_athena_query()` 폴링 횟수 증가 또는 Lambda timeout 증가

### Lambda 에러 확인

```
CloudWatch > 로그 그룹:
- /aws/lambda/BedrockAthenaLogQueryLambda
- /aws/lambda/BedrocBlockAlertLambda

주요 패턴:
- [INFO] Saved X items → 정상 집계
- [INFO] Currently blocked sessions: N → 현재 차단 인원
- [NEW BLOCK] user@example.com ($XX.XX) → 신규 차단
- [ERROR] → 오류 발생
```

## 2. Lambda 함수 Trigger 방식

Lambda 함수는 **Event 기반**과 **Schedule 기반** 두 가지 방식으로 실행됩니다.

### Schedule (자동 실행)

Lambda 함수는 **EventBridge Scheduler를 통해 5분 주기**로 실행됩니다.

```
EventBridge → Scheduler → Schedules → BedrockAthenaLogQueryLambda-Schedule
```

- 실행 주기: `rate(5 minutes)`
- 타임존: `Asia/Seoul` (KST)
- Flexible Time Window: OFF (정시 실행)

### Event (수동 실행)

```
Lambda 콘솔 → BedrockAthenaLogQueryLambda → Test → Payload를 {}으로 → Invoke
```

## 3. 전체 시스템 흐름

```
EventBridge Scheduler (5분 주기)
        │
        ▼
BedrockAthenaLogQueryLambda
  │  1. Athena로 당월 Bedrock 호출 로그 조회 (KST 기준)
  │  2. 토큰 기반 사용자별 비용 계산
  │  3. DynamoDB에 월별 비용 저장 (bedrock-budget-user-costs)
  │  4. DynamoDB에 일별 로그 저장 (bedrock-budget-user-costs-log)
  │
  └──(InvocationType="Event", 비동기)──▶ BedrocBlockAlertLambda
                                           │  1. DynamoDB에서 당월 비용 데이터 읽기
                                           │  2. 사용자별 예산 한도 조회
                                           │  3. 기존 차단자 조회
                                           │  4. 예산 초과 사용자 신규/기존 분류
                                           │  5. IAM Deny 정책 분배 및 적용
                                           └──▶ 신규 차단자에게 SES 이메일 발송 (설정 시)
```

### 4-3. `build_profile_mapping()`

- Bedrock `list_inference_profiles` API를 호출하여 **Application Inference Profile ID → 실제 모델 ARN** 매핑 테이블을 빌드합니다.
- Lambda 콜드 스타트 시 모듈 레벨(`PROFILE_MAP`)에서 한 번만 실행되어 재사용됩니다.
- API 호출 실패 시 경고 로그만 남기고 빈 dict를 반환합니다.

### 4-4. `get_model_tier(model_id)`

- `model_id` 문자열에서 모델 티어 키를 추출합니다.
- Application Inference Profile ARN인 경우 `PROFILE_MAP`을 통해 실제 모델 ARN으로 역참조 후 재판별합니다.
- 매핑 우선순위:

```
opus-4-8 > opus-4-7 > opus-4-6 > opus-4-5 > opus(fallback→opus-4-8)
> sonnet-5 > sonnet-4-6 > sonnet-4-5 > sonnet-4
> haiku > 기본값(sonnet-4-6)
```

### 4-5. `get_current_date()`

- **KST (UTC+9)** 기준으로 현재 `YYYY-MM`, `YYYY-MM-DD` 형식을 반환합니다.
- DynamoDB 키(month, date) 생성에 사용됩니다.

### 4-6. `run_athena_query(query_string)`

- Athena에 쿼리를 제출하고 **최대 50회 (3초 간격, 총 150초)** 폴링하여 완료를 기다립니다.
- `SUCCEEDED` 시 `QueryExecutionId`를 반환
- `FAILED`/`CANCELLED`/타임아웃 시 예외를 발생시킵니다.

### 4-7. `get_athena_results(qid)`

- `get_query_results` paginator를 사용하여 전체 결과를 dict 리스트로 반환합니다.
- 첫 번째 행은 헤더로 처리하여 이후 행과 zip하여 컬럼명 매핑합니다.

### 4-8. `_boundary_partitions(year, month)`

- S3 파티션이 로그 전송 시각 기준으로 생성되어 실제 API 호출 시각과 최대 2시간 차이가 날 수 있습니다.
- 월 경계의 cross-month 중복 집계 방지를 위해 **전월 마지막 날**과 **차월 1일** 파티션 정보를 함께 반환합니다.

### 4-9. `query_bedrock_logs(year, month)` — 핵심 집계 쿼리

**시간대 처리 (KST 기준):**
```python
# KST 기준 당월 시작 → UTC 변환
# 예: 2026-07-01 00:00 KST → 2026-06-30 15:00:00Z UTC
kst_start = start_kst.astimezone(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")

# KST 기준 차월 시작 → UTC 변환  
# 예: 2026-08-01 00:00 KST → 2026-07-31 15:00:00Z UTC
kst_end = end_kst.astimezone(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
```

**Athena 쿼리 구조:**
```sql
WITH deduped AS (
    SELECT
        identity.arn AS identity_arn,
        modelid AS modelId,
        input.inputTokenCount AS input_tokens,
        COALESCE(input.cacheReadInputTokenCount, 0) AS cache_read_tokens,
        COALESCE(input.cacheWriteInputTokenCount, 0) AS cache_write_tokens,
        output.outputTokenCount AS output_tokens,
        ROW_NUMBER() OVER (
            PARTITION BY requestid
            ORDER BY (총 토큰 합계) DESC
        ) AS rn
    FROM invocations
    WHERE (dt 파티션 범위: 당월 + 전월 마지막 날 + 차월 첫날)
      AND timestamp >= '{kst_start}' AND timestamp < '{kst_end}'
)
SELECT identity_arn, modelId,
       SUM(각 토큰), COUNT(*) AS invocations
FROM deduped WHERE rn = 1
GROUP BY identity_arn, modelId
```

**중복 제거 전략:**
- `requestid` 기준 `ROW_NUMBER()`: 동일 호출의 중복 레코드 중 토큰 합계가 가장 큰 것만 유지
- 스트리밍 시작 레코드(0 토큰), 크로스리전 지연 복사본 등 자동 제거

### 4-10. `calculate_costs(rows, is_long_context=False)`

**비용 산출 공식:**
```
사용자 비용 = Σ (모델별)
  (input_tokens × input_price / 1,000,000)
+ (cache_read_tokens × cache_read_price / 1,000,000)
+ (cache_write_tokens × cache_write_price / 1,000,000)
+ (output_tokens × output_price / 1,000,000)
```

**현재 적용 중인 가격표 (USD per 1M tokens):**

| 모델 | Input | Output | Cache Write | Cache Read |
|------|-------|--------|-------------|------------|
| opus-4-8 | $5.00 | $25.00 | $6.250 | $0.50 |
| opus-4-7 | $5.00 | $25.00 | $6.250 | $0.50 |
| opus-4-6 | $5.00 | $25.00 | $6.250 | $0.50 |
| opus-4-5 | $5.00 | $25.00 | $6.250 | $0.50 |
| sonnet-5 | $2.00 | $10.00 | $2.500 | $0.20 |
| sonnet-4-6 | $3.00 | $15.00 | $3.750 | $0.30 |
| haiku-4-5 | $1.00 | $5.00 | $1.250 | $0.10 |

- `is_long_context=False`로 고정 호출되어 현재 long context 분기는 실행되지 않습니다.

def lambda_handler(event, context):

### 5-3. `load_user_costs_from_dynamodb(year_month)`

- DynamoDB `bedrock-budget-user-costs` 테이블에서 `month = {당월}` 조건으로 Query

### 5-4. `get_user_budget()`

- `bedrock-budget-user-budget` 테이블 전체 Scan
- 동일 사용자가 여러 월에 걸쳐 존재할 경우 **가장 최신 month**의 `budget_limit`만 사용
- 해당 사용자 레코드가 없으면 환경변수 `BUDGET_LIMIT` (기본 $60) 적용

### 5-5. 예산 초과 판정

```python
if info["cost"] > float(user_budget_table.get(arn, {}).get('budget_limit', BUDGET_LIMIT)):
    # 차단 대상
```

- 개인별 한도 > 기본값 순으로 판정
- 초과 시 해당 사용자의 세션 이름(이메일)을 차단 목록에 추가

### 5-6. IAM Deny 정책 차단 메커니즘

**정책 구조:**
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyBedrockForBudgetExceededUsers",
    "Effect": "Deny",
    "Action": [
      "bedrock:InvokeModel",
      "bedrock:InvokeModelWithResponseStream"
    ],
    "Resource": "*",
    "Condition": {
      "StringLike": {
        "aws:userid": ["*:user1@example.com", "*:user2@example.com"]
      }
    }
  }]
}
```

**동작 방식:**
- `aws:userid`의 세션 이름(이메일)으로 사용자 식별
- Deny 정책이 Allow보다 우선 → 해당 사용자는 Bedrock 호출 불가
- 정책은 `AWSReservedSSO_ClaudeCodeAccess_<sso-role-id>` 및 `ClaudeCodeAccess` 역할에 연결됨

**정책 분배:**
- 차단 대상 세션 이름을 정렬 후 150명씩 나누어 `BedrockBudgetDeny_1` ~ `_9`에 순차 배치
- 빈 정책은 placeholder로 초기화 (nobody 조건)
- 최대 차단 가능 인원: **9 × 150 = 1,350명**

### 5-8. SES 이메일 알림

- 현재 `SES_SENDER_EMAIL`이 비어있어 **이메일 발송 비활성화 상태**
- 활성화 시: 신규 차단자에게 예산 초과 안내 + 모델별 사용 내역 이메일 발송
- 수신자: 발신자와 동일 주소 (관리자에게 전달)

### 5-9. 자동 해제 (복구)

- 매월 1일 (KST 기준) 새 집계 시작 → 모든 사용자 비용 0
- 다음 사이클(5분 내)에 Deny 정책에서 자동 제거
- 별도 "해제" 로직 없음. **비용 < 한도**이면 정책에서 자동으로 빠짐

## 6. API Gateway — 사용자 조회 API

### 6-1. bedrock-budget-api

**엔드포인트**: `https://<budget-api-id>.execute-api.ap-northeast-2.amazonaws.com/prod`  
**인증**: AWS IAM (SigV4)

| 경로 | 메서드 | Lambda | 설명 |
|------|--------|--------|------|
| `/usage` | GET | `BedrockBudget-GetMyUsage` | 호출자 본인 당월 사용량 |
| `/budget` | GET | `BedrockBudget-ManageUserBudget` | 예산 한도 조회 |
| `/budget` | PUT | `BedrockBudget-ManageUserBudget` | 예산 한도 변경 |
| `/dailylog` | GET | `BedrockBudget-GetDailyCostLog` | 일별 비용 로그 |

#### `BedrockBudget-GetMyUsage` 동작
- API Gateway가 전달하는 `event["requestContext"]["identity"]["userArn"]`에서 호출자 식별
- SSO 환경에서는 `IDENTITY_ARN_TEMPLATE` 환경변수로 identity_arn 형식 지정
- DynamoDB에서 해당 사용자의 당월 비용 + 개인별 한도 조회 후 반환

#### `BedrockBudget-ManageUserBudget` 동작
- GET: 전체 또는 특정 사용자의 예산 한도 조회
- PUT: `{ "month", "identity_arn", "budget_limit" }` 형태로 예산 설정

#### `BedrockBudget-GetDailyCostLog` 동작
- `?date=YYYY-MM-DD` 파라미터로 특정 일자 조회
- 파라미터 없으면 전체 Scan

### 6-2. bedrock-compliance-api

**엔드포인트**: `https://<compliance-api-id>.execute-api.ap-northeast-2.amazonaws.com/prod`  
**인증**: AWS IAM (SigV4)

| 경로 | 메서드 | 설명 |

## 7. 호출부터 차단까지 소요 시간 

```
[T+0분] 사용자가 Bedrock API 호출
[T+1~5분] Invocation Logging → S3에 로그 적재
[T+5~10분] EventBridge Scheduler가 BedrockAthenaLogQueryLambda 실행
[T+10~12분] Athena 쿼리 완료 → DynamoDB 저장
[T+12~13분] BedrocBlockAlertLambda 실행 → IAM 정책 업데이트
```

**최대 지연**: 약 10~15분 (로그 적재 지연 + 집계 주기)

> ⚠️ 실시간 차단이 아닌 **준실시간(near real-time)** 시스템입니다. 사용자가 한도를 초과한 후 최대 10~15분간 추가 호출이 가능합니다.
